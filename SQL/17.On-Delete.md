# On Delete

## What is ON DELETE?
- Defines what happens to a row when a referenced row in another table is deleted
- Set when defining a foreign key
- Handles the issue of dangling/orphaned foreign key references

---

## Two Main Options

### ON DELETE SET NULL
- When the referenced row is deleted → foreign key column is set to `NULL`
- Use when the row can still exist without the reference

```sql
CREATE TABLE branch (
    branch_id INT PRIMARY KEY,
    branch_name VARCHAR(40),
    mgr_id INT,
    FOREIGN KEY(mgr_id) REFERENCES employee(emp_id) ON DELETE SET NULL
);
```
- If the manager (employee) is deleted → `mgr_id` becomes `NULL`
- The branch row still exists, just without a manager

### ON DELETE CASCADE
- When the referenced row is deleted → the row containing the foreign key is also deleted
- Use when the row has no meaning without the reference

```sql
CREATE TABLE branch_supplier (
    branch_id INT,
    supplier_name VARCHAR(40),
    PRIMARY KEY(branch_id, supplier_name),
    FOREIGN KEY(branch_id) REFERENCES branch(branch_id) ON DELETE CASCADE
);
```
- If the branch is deleted → all related branch_supplier rows are also deleted

---

## When to Use Which

| Scenario | Use |
|----------|-----|
| Row can exist without the reference | `ON DELETE SET NULL` |
| Row is meaningless without the reference | `ON DELETE CASCADE` |
| Column is part of a composite primary key | `ON DELETE CASCADE` (can't set PK to NULL) |

---

## Notes
- `ON DELETE SET NULL` won't work if the foreign key column is also a `PRIMARY KEY` or `NOT NULL`
- `ON DELETE CASCADE` can cause a chain reaction — deleting one row can delete many others
- Default behavior (no ON DELETE specified) → error if you try to delete a referenced row
