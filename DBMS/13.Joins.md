# Joins

## What are Joins?
- Used to combine data from two or more tables based on a related attribute
- Core operation in relational databases
- Different types depending on how unmatched rows are handled

---

## Why Joins?
- Data is spread across multiple tables (due to normalization)
- Joins let you retrieve combined/related data in a single query

---

## Inner Join (Default Join)

- Returns only rows where there is a **match in both tables**
- Unmatched rows from either side are excluded

### Example
```sql
SELECT e.name, b.branch_name
FROM employee e
JOIN branch b ON e.branch_id = b.branch_id;
```
- Only employees who have a matching branch are returned

---

## Natural Join

- A special inner join where the join is done on **all columns with the same name**
- Automatically matches columns with identical names
- Duplicate columns are removed from the result

### Example
```sql
SELECT * FROM employee NATURAL JOIN branch;
```
- Joins on all common column names (e.g. `branch_id` if it exists in both)

### Note
- Convenient but risky — if an unintended column has the same name in both tables, it will be joined on that too
- Explicit joins are safer and clearer

---

## Self Join

- A table joined with **itself**
- Used when a table has a self-referencing relationship
- Must use aliases to distinguish the two instances

### Example
- Find all employees and their managers (manager is also an employee)
```sql
SELECT e.name AS employee, m.name AS manager
FROM employee e
JOIN employee m ON e.super_id = m.emp_id;
```

---

## Equi Join

- A join based on equality condition between columns
- The ON clause uses `=`
- Inner join is a type of equi join
- Result includes the join column from both tables (unlike natural join which removes duplicates)

### Example
```sql
SELECT e.name, b.branch_name
FROM employee e, branch b
WHERE e.branch_id = b.branch_id;
```

### Equi Join vs Natural Join
| | Equi Join | Natural Join |
|-|-----------|--------------|
| Column specified | Yes | No (auto) |
| Duplicate columns | Yes | Removed |
| Control | More | Less |

---

## Left Outer Join

- Returns **all rows from the left table** + matched rows from the right
- If no match in right table → NULL for right table columns

### Example
```sql
SELECT e.name, b.branch_name
FROM employee e
LEFT JOIN branch b ON e.branch_id = b.branch_id;
```
- All employees returned, even those without a branch
- `branch_name` = NULL for employees with no matching branch

---

## Right Outer Join

- Returns **all rows from the right table** + matched rows from the left
- If no match in left table → NULL for left table columns

### Example
```sql
SELECT e.name, b.branch_name
FROM employee e
RIGHT JOIN branch b ON e.branch_id = b.branch_id;
```
- All branches returned, even those with no employees
- `e.name` = NULL for branches with no matching employee

---

## Full Outer Join

- Returns all rows from **both tables**
- NULL where there is no match on either side
- Not natively supported in MySQL — simulate with LEFT JOIN UNION RIGHT JOIN

### Example (simulated in MySQL)
```sql
SELECT e.name, b.branch_name
FROM employee e
LEFT JOIN branch b ON e.branch_id = b.branch_id
UNION
SELECT e.name, b.branch_name
FROM employee e
RIGHT JOIN branch b ON e.branch_id = b.branch_id;
```

---

## Join Summary

| Join Type | Left Unmatched | Right Unmatched |
|-----------|---------------|-----------------|
| Inner Join | Excluded | Excluded |
| Left Outer Join | Included (NULL right) | Excluded |
| Right Outer Join | Excluded | Included (NULL left) |
| Full Outer Join | Included (NULL right) | Included (NULL left) |
| Natural Join | Same as Inner, auto column match | — |
| Self Join | Table joined with itself | — |

---

## Notes
- `JOIN` without a type = `INNER JOIN` by default
- Always specify `table.column` when column names exist in both tables
- Natural join is convenient but less safe — prefer explicit joins
- Self join always needs aliases
- Left/Right outer joins are the most commonly used outer joins in practice
