# Normalization - Introduction

## What is Normalization?
- Process of organizing a database to reduce redundancy and improve data integrity
- Achieved by decomposing large tables into smaller, well-structured ones
- Each normal form (NF) has a set of rules — higher NF = more refined structure

---

## Why Normalize?
- Eliminate data redundancy (same data stored multiple times)
- Avoid anomalies that occur during insert, update, and delete operations

---

## Anomalies (Problems in Unnormalized Data)

### Insertion Anomaly
- Cannot insert data without having other unrelated data
- e.g. cannot add a new course unless at least one student is enrolled in it
- The course info is trapped inside the student-course table

### Deletion Anomaly
- Deleting one piece of data unintentionally removes other important data
- e.g. deleting the only student enrolled in a course → course info is also lost

### Updation (Update) Anomaly
- Updating one piece of data requires updating it in multiple places
- If one is missed → inconsistency
- e.g. changing a professor's name requires updating every row where they appear

---

## Normal Forms Overview

| Normal Form | What it fixes |
|-------------|---------------|
| 1NF | Atomicity — no repeating groups or multi-valued cells |
| 2NF | Removes partial dependencies (on part of a composite key) |
| 3NF | Removes transitive dependencies |
| BCNF | Stricter version of 3NF |
| 4NF | Removes multi-valued dependencies |
| 5NF | Removes join dependencies |

---

## First Normal Form (1NF)

### Rules
- Every column must have **atomic** (indivisible) values
- No repeating groups or arrays in a single cell
- Each row must be unique (has a primary key)
- Each cell contains only one value

### Example — NOT in 1NF
| student_id | name | courses         |
|------------|------|-----------------|
| 1          | Jack | Math, Physics   |
| 2          | Kate | Chemistry       |

- `courses` column has multiple values → violates 1NF

### Fixed — In 1NF
| student_id | name | course    |
|------------|------|-----------|
| 1          | Jack | Math      |
| 1          | Jack | Physics   |
| 2          | Kate | Chemistry |

- Each cell now has one atomic value
- Primary key becomes composite: `(student_id, course)`

---

## Notes
- Normalization is a design-time process — done before or during schema design
- Over-normalization can hurt performance due to too many joins
- Most real-world databases aim for 3NF or BCNF
- Denormalization is sometimes done intentionally for performance
