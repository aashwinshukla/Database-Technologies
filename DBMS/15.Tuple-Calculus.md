# Tuple Calculus

## What is it?
- A non-procedural query language for relational databases
- Describes **what** data to retrieve, not **how** to retrieve it
- Based on mathematical logic (predicate calculus)
- Contrast with relational algebra which is procedural (step by step)

---

## Tuple vs Domain Calculus
- **Tuple Relational Calculus (TRC)** — variables represent tuples (rows)
- **Domain Relational Calculus (DRC)** — variables represent individual attribute values
- TRC is more commonly used and discussed

---

## Tuple Relational Calculus (TRC)

### Basic Form
```
{ t | P(t) }
```
- `t` = a tuple variable (represents a row)
- `P(t)` = a predicate/condition that t must satisfy
- Read as: "the set of all tuples t such that P(t) is true"

---

## Notation

### Accessing an attribute
```
t.attribute_name
```
- e.g. `t.name`, `t.salary`

### Membership in a relation
```
t ∈ Employee  or  Employee(t)
```
- t is a tuple in the Employee relation

---

## Examples

### Get all employees
```
{ t | t ∈ Employee }
```

### Get names of all employees
```
{ t.name | t ∈ Employee }
```

### Get employees with salary > 50000
```
{ t | t ∈ Employee AND t.salary > 50000 }
```

### Get names of employees in branch 2
```
{ t.name | t ∈ Employee AND t.branch_id = 2 }
```

### Get employees who work with client 101
```
{ t | t ∈ Employee AND ∃s (s ∈ Works_With AND s.emp_id = t.emp_id AND s.client_id = 101) }
```

---

## Quantifiers

### Existential Quantifier (∃)
- "There exists at least one"
- `∃t (P(t))` = there exists a tuple t such that P(t) is true
- Used for "at least one" conditions

### Universal Quantifier (∀)
- "For all"
- `∀t (P(t))` = for every tuple t, P(t) is true
- Used for "all" conditions (similar to division in relational algebra)

### Example with ∀
- Get employees who have worked with every client:
```
{ t | t ∈ Employee AND ∀s (s ∈ Client → ∃w (w ∈ Works_With AND w.emp_id = t.emp_id AND w.client_id = s.client_id)) }
```

---

## Safe Expression
- A TRC expression is **safe** if it only produces finite results
- Unsafe expressions can produce infinite results
- e.g. `{ t | NOT (t ∈ Employee) }` — could return infinitely many tuples not in Employee
- Only safe expressions are considered valid queries

---

## Relational Completeness
- A query language is **relationally complete** if it can express any query that relational algebra can express
- TRC is relationally complete
- SQL is also relationally complete (based on TRC concepts)

---

## Relational Algebra vs Tuple Calculus

| | Relational Algebra | Tuple Calculus |
|-|--------------------|----------------|
| Type | Procedural | Non-procedural |
| Focus | How to get data | What data to get |
| Style | Step-by-step operations | Logical conditions |
| Base | Set theory | Predicate logic |

---

## Notes
- TRC is the theoretical foundation behind SQL's declarative style
- In practice, SQL is used — TRC is important for understanding the theory
- ∃ maps roughly to SQL's EXISTS / IN
- ∀ maps roughly to SQL's NOT EXISTS with a negated condition
- Safe expressions = expressions that always produce finite, meaningful results
