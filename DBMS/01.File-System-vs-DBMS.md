# File System vs DBMS

## What is a File System?
- Traditional way of storing data before DBMS
- Data stored in separate files on disk
- Each application manages its own files
- e.g. HR department has its own files, Accounts has its own — no sharing

---

## Disadvantages of File System

### 1. Data Redundancy
- Same data stored in multiple files across departments
- e.g. employee name stored in both HR file and Payroll file
- Wastes storage space

### 2. Data Inconsistency
- If data is updated in one file but not others → inconsistent data
- e.g. address updated in HR file but not in Payroll file

### 3. Difficulty in Accessing Data
- No query language — have to write custom programs to retrieve data
- Every new query = new program

### 4. Data Isolation
- Data scattered in different files and formats
- Hard to retrieve data that spans multiple files

### 5. Integrity Problems
- Hard to enforce rules/constraints on data
- e.g. ensuring age is always > 18 is not straightforward

### 6. Atomicity Problems
- If a system crash occurs mid-operation, partial updates may happen
- e.g. money deducted from account A but not added to account B

### 7. Concurrent Access Issues
- Multiple users accessing/modifying the same file simultaneously → data corruption

### 8. Security Problems
- Difficult to apply fine-grained access control
- Either full access or no access — no in-between

---

## How DBMS Solves These

| File System Problem | DBMS Solution |
|--------------------|---------------|
| Data redundancy | Centralized storage, normalization |
| Data inconsistency | Single source of truth |
| No query language | SQL for easy data retrieval |
| No integrity enforcement | Constraints (PRIMARY KEY, NOT NULL, etc.) |
| Atomicity issues | Transactions with rollback support |
| Concurrency issues | Concurrency control mechanisms |
| Security issues | Role-based access control |

---

## Notes
- File systems still used for non-structured data (images, videos, logs)
- DBMS is preferred whenever structured, relational data needs to be managed
- DBMS has overhead — for very simple data, a file system may still be used
