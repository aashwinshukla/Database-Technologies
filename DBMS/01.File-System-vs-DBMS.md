# File System vs DBMS

## File System
- Traditional way of storing data before DBMS
- Data stored in separate files, each application manages its own
- No central control or coordination between files

## Disadvantages of File System

### Data Redundancy
- Same data stored in multiple places
- e.g. employee name stored in both HR file and Payroll file
- Wastes storage

### Data Inconsistency
- If data is updated in one file but not others → inconsistent state
- e.g. address updated in HR but not Payroll

### Difficult Data Access
- No query language — need custom programs for every new request
- Not flexible at all

### Data Isolation
- Data scattered in different files and formats
- Hard to combine data across files

### Integrity Problems
- No easy way to enforce rules on data
- e.g. ensuring a field is always positive requires custom code

### Atomicity Problems
- Partial updates can happen during a crash
- e.g. money debited from one account but not credited to another

### Concurrency Issues
- Multiple users modifying the same file → data corruption

### Security Issues
- Hard to give fine-grained access — either full access or none

---

## How DBMS Fixes These

| Problem | DBMS Solution |
|---------|---------------|
| Redundancy | Centralized storage, normalization |
| Inconsistency | Single source of truth |
| No query language | SQL |
| No integrity rules | Constraints (PK, FK, NOT NULL, etc.) |
| Atomicity | Transactions with rollback |
| Concurrency | Concurrency control |
| Security | Role-based access control |

---

## Notes
- File systems still used for unstructured data (images, videos, logs)
- DBMS adds overhead — for very simple needs, a file might still work
- For anything structured and relational, DBMS is the right choice
