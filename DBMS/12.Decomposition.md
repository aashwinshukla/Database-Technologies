# Decomposition

## What is Decomposition?
- Breaking a relation into two or more smaller relations
- Done to eliminate redundancy and anomalies (normalization)
- The smaller relations should together represent the same information as the original

---

## Properties of a Good Decomposition

### 1. Lossless Decomposition
- The original relation can be perfectly reconstructed by joining the decomposed relations
- No spurious (extra/wrong) tuples are generated on joining
- This is a **mandatory** property — always required

#### Test for Lossless (Binary Decomposition)
- Decompose R into R1 and R2
- Lossless if: `(R1 ∩ R2) → R1` OR `(R1 ∩ R2) → R2`
- i.e. the common attributes must be a superkey in at least one of the two relations

#### Example
- R(A, B, C), FD: A → B
- Decompose into R1(A, B) and R2(A, C)
- R1 ∩ R2 = {A}
- A → B means A is a superkey in R1(A, B) ✓
- Lossless decomposition

### 2. Dependency Preserving Decomposition
- All original functional dependencies can still be checked using the decomposed relations
- No FD should require joining tables back together just to verify it
- This is a **desirable** property — not always achievable (especially with BCNF)

---

## Dependency Preserving Decomposition

### Definition
- A decomposition of R into R1, R2, ..., Rn is dependency preserving if:
  - The union of FDs in each Ri (projected onto Ri) covers all original FDs
  - i.e. (F1 ∪ F2 ∪ ... ∪ Fn)⁺ = F⁺

### How to Check
1. For each FD X → Y in the original set
2. Check if X → Y can be derived using only the FDs within the decomposed relations
3. If every FD can be derived → dependency preserving

### Example 1 — Dependency Preserving
- R(A, B, C), FDs: A → B, B → C
- Decompose into R1(A, B) and R2(B, C)
- R1 preserves: A → B ✓
- R2 preserves: B → C ✓
- All FDs preserved → dependency preserving ✓

### Example 2 — NOT Dependency Preserving
- R(A, B, C), FDs: A → B, B → C, A → C
- Decompose into R1(A, B) and R2(A, C)
- R1 preserves: A → B ✓
- R2 preserves: A → C ✓
- B → C — B is not in R1 alone fully, C is not in R1, B and C not together in any relation
- B → C cannot be checked without joining → NOT dependency preserving ✗

---

## Lossless vs Dependency Preserving

| Property | Required? | Lost in |
|----------|-----------|---------|
| Lossless | Always | Should never be lost |
| Dependency Preserving | Preferred | Sometimes lost in BCNF |

- 3NF decomposition always achieves both lossless AND dependency preserving
- BCNF decomposition always achieves lossless but may NOT preserve dependencies

---

## Algorithm for Dependency Preserving Check

1. For each FD X → Y to verify:
   - Compute closure of X using only FDs within the decomposed relations
   - If Y ⊆ closure of X → the FD is preserved
2. If all FDs are preserved → decomposition is dependency preserving

---

## Notes
- Lossless is non-negotiable — a lossy decomposition is useless
- Dependency preservation makes enforcement easier — no joins needed to check constraints
- When BCNF breaks dependency preservation, 3NF is preferred as a compromise
- Always verify both properties when decomposing a relation
