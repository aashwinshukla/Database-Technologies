# Normalization - Practice

## How to Find the Normal Form of a Relation

### Step 1 — Check 1NF
- Are all attributes atomic?
- No repeating groups?
- If no → not even in 1NF

### Step 2 — Identify the Primary Key
- Find all candidate keys using closure
- The one chosen is the PK
- Prime attributes = attributes that are part of any candidate key
- Non-prime attributes = everything else

### Step 3 — Check 2NF
- Is the PK composite?
  - If no → automatically in 2NF (no partial dependencies possible)
  - If yes → check if any non-prime attribute depends on only part of the PK
- If partial dependency exists → not in 2NF

### Step 4 — Check 3NF
- Does any non-prime attribute depend on another non-prime attribute?
- i.e. is there a transitive dependency?
- If yes → not in 3NF

### Step 5 — Check BCNF
- For every FD X → Y, is X a superkey?
- If any FD has a non-superkey determinant → not in BCNF

## How to Solve Normalization Problems

### General Approach
1. List all given functional dependencies
2. Find all candidate keys (use closure)
3. Identify prime and non-prime attributes
4. Check each normal form condition one by one
5. Decompose if needed — ensure lossless + dependency preserving

### Finding Candidate Keys
- Try closure of each attribute or combination
- If closure = all attributes → it's a candidate key
- Check minimality — remove attributes one by one, if closure still = all attributes → not minimal

### Decomposing to 2NF
- For each partial dependency X → Y (where X is part of PK):
  - Create a new table with X as PK and Y as attribute
  - Remove Y from the original table
  - Keep the full PK + remaining non-prime attributes in the original

### Decomposing to 3NF
- For each transitive dependency X → Y → Z:
  - Create a new table (Y, Z) with Y as PK
  - Remove Z from the original table
  - Keep X → Y in the original

### Decomposing to BCNF
- For each FD X → Y where X is not a superkey:
  - Create new table (X, Y) with X as PK
  - Remove Y from the original table
  - Check if decomposition is lossless
  - Note: may not preserve all FDs

## Example Walkthrough

### Given
- Relation R(A, B, C, D, E)
- FDs: A → B, BC → D, B → E

### Step 1 — Find Candidate Keys
- Closure of A: A → B (add B), B → E (add E) → {A, B, E} — not all attributes
- A alone can't determine C or D
- Try AC: A → B, B → E, BC → D → {A, B, C, D, E} ✓ → AC is a candidate key
- Check minimality: C alone → only {C}, A alone → {A, B, E} → neither works alone
- Candidate key = AC

### Step 2 — Prime and Non-prime
- Prime attributes: A, C (in candidate key AC)
- Non-prime attributes: B, D, E

### Step 3 — Check 2NF
- PK = AC (composite)
- A → B → B is non-prime, depends on only A (part of PK) → partial dependency → NOT in 2NF

### Step 4 — Decompose to 2NF
- R1(A, B, E) — A is PK, B and E depend on A
- R2(A, C, D) — AC is PK, D depends on AC

### Step 5 — Check 3NF on R1
- In R1: A → B, B → E
- B is non-prime, E is non-prime, B → E → transitive dependency → NOT in 3NF

### Decompose R1 to 3NF
- R1a(A, B) — A is PK
- R1b(B, E) — B is PK

### Final Tables
- R1a(A, B)
- R1b(B, E)
- R2(A, C, D)

## Common Mistakes to Avoid
- Forgetting to check minimality when finding candidate keys
- Assuming single-attribute PK = automatically in 2NF (correct) but not necessarily 3NF
- Confusing prime and non-prime attributes
- Not verifying lossless decomposition after splitting
- Missing transitive dependencies that go through multiple steps

---

## Notes
- Always find candidate keys before checking normal forms
- Decomposition should always be lossless — verify using the intersection rule
- Dependency preservation is preferred but not always possible with BCNF
- Practice with different FD sets — the pattern becomes intuitive quickly
