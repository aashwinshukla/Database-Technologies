# Relational Algebra

## What is it?
- A procedural query language for relational databases
- Works on relations (tables) and returns a relation as output
- Foundation of SQL — SQL is based on relational algebra concepts
- Operations take one or two relations as input and produce a new relation

---

## Types of Operations
- **Unary** — operate on a single relation (Select, Project, Rename)
- **Binary** — operate on two relations (Union, Set Difference, Cartesian Product, Join, Division)

---

## Selection (σ)

- Filters rows based on a condition
- Returns a subset of tuples that satisfy the predicate
- Unary operation

### Notation
```
σ condition (R)
```

### Example
```
σ salary > 50000 (Employee)
σ sex = 'M' AND branch_id = 2 (Employee)
```

### Notes
- Condition can use: =, ≠, <, >, ≤, ≥, AND, OR, NOT
- Output has same columns as input, fewer rows

---

## Projection (π)

- Selects specific columns from a relation
- Removes duplicate rows from the result automatically
- Unary operation

### Notation
```
π column1, column2 (R)
```

### Example
```
π name, salary (Employee)
π branch_id (Employee)
```

### Notes
- Output has fewer columns, same or fewer rows (duplicates removed)
- Combine with selection: `π name (σ salary > 50000 (Employee))`

---

## Cross Product / Cartesian Product (×)

- Combines every row of one relation with every row of another
- If R has m rows and S has n rows → result has m × n rows
- Binary operation

### Notation
```
R × S
```

### Example
```
Employee × Branch
```
- If Employee has 5 rows and Branch has 3 rows → result has 15 rows

### Notes
- Rarely useful on its own — typically followed by a selection to form a join
- Column count = columns in R + columns in S

---

## Set Difference (−)

- Returns rows that are in R but NOT in S
- Binary operation

### Notation
```
R − S
```

### Conditions
- R and S must be union-compatible (same number of columns, compatible types)

### Example
```
AllEmployees − Managers
```
- Returns employees who are not managers

---

## Union (∪)

- Returns all rows from both relations, removing duplicates
- Binary operation

### Notation
```
R ∪ S
```

### Conditions
- R and S must be union-compatible

### Example
```
MaleEmployees ∪ FemaleEmployees
```

### Notes
- Duplicates are automatically removed
- Use carefully — both relations must have the same schema structure

---

## Division (÷)

- Returns rows from R that are associated with **all** rows in S
- Used for "for all" type queries
- Binary operation

### Notation
```
R ÷ S
```

### Example
- R = `Works_With(emp_id, client_id)`
- S = `AllClients(client_id)`
- `R ÷ S` = employees who have worked with **every** client

### When to use
- "Find employees who work with all clients"
- "Find students who have taken all courses"

---

## Rename (ρ)

- Renames a relation or its attributes
- Used to avoid ambiguity, especially in self-joins or when combining relations

### Notation
```
ρ new_name (R)
ρ new_name(attr1, attr2, ...) (R)
```

### Example
```
ρ Emp(id, name, salary) (Employee)
```

### When to use
- Self-join: rename the same table to two different names
- Intermediate results: give a name to a derived relation

---

## Combining Operations

### Find names of employees earning more than 50000
```
π name (σ salary > 50000 (Employee))
```

### Find names of employees in branch 2
```
π name (σ branch_id = 2 (Employee))
```

### Join using Cartesian Product + Selection
```
π emp_name, branch_name (σ Employee.branch_id = Branch.branch_id (Employee × Branch))
```
- This is essentially an inner join expressed in relational algebra

---

## Summary Table

| Operation | Symbol | Type | What it does |
|-----------|--------|------|--------------|
| Selection | σ | Unary | Filters rows by condition |
| Projection | π | Unary | Selects specific columns |
| Rename | ρ | Unary | Renames relation/attributes |
| Union | ∪ | Binary | All rows from both, no duplicates |
| Set Difference | − | Binary | Rows in R but not in S |
| Cartesian Product | × | Binary | Every row of R with every row of S |
| Division | ÷ | Binary | Rows in R associated with all rows in S |

---

## Notes
- Relational algebra is closed — output of every operation is also a relation
- Operations can be nested/chained
- SQL SELECT ≈ projection, WHERE ≈ selection, FROM two tables ≈ cartesian product
- Division is the trickiest — think of it as "for all" queries
