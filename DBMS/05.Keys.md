# Keys

## Why Keys?
- Uniquely identify rows in a table
- Establish relationships between tables
- Foundation of relational database design

---

## Super Key
- Any set of attributes that can uniquely identify a row
- Does NOT have to be minimal
- e.g. `{student_id}`, `{roll_no}`, `{student_id, name}` are all super keys

---

## Candidate Key
- A **minimal** super key — no subset of it can also uniquely identify a row
- A table can have multiple candidate keys
- e.g. if `student_id` and `roll_no` both uniquely identify rows → both are candidate keys
- `{student_id, name}` is a super key but NOT a candidate key (not minimal)

---

## Primary Key
- The candidate key chosen to uniquely identify rows in a table
- Only ONE primary key per table
- Cannot be NULL, cannot have duplicates
- Prefer stable, simple attributes — or use a surrogate (auto-incremented) key

---

## Alternate Key
- Candidate keys that were not chosen as the primary key
- Still unique, just not the designated PK
- e.g. if `student_id` is PK, then `roll_no` is an alternate key

---

## Foreign Key
- An attribute that references the primary key of another table
- Used to link tables and enforce referential integrity
- Can be NULL (unless NOT NULL constraint is added)
- Can have duplicate values (unlike PK)

### Rules
- FK value must exist as a PK in the referenced table OR be NULL
- FK and PK must have compatible data types
- Must insert into the parent table before the child table

### Self-referencing FK
- FK referencing a PK in the same table
- e.g. `super_id` in employee table referencing `emp_id` in the same table

---

## ON DELETE Behavior with FK

### ON DELETE CASCADE
- Deleting a parent row → automatically deletes all child rows with that FK
- Use when child rows have no meaning without the parent

### ON DELETE SET NULL
- Deleting a parent row → FK in child rows is set to NULL
- Use when child rows can still exist without the parent

---

## Relationship Between Key Types
```
Super Key ⊇ Candidate Key ⊇ Primary Key
```
- All candidate keys are super keys
- Not all super keys are candidate keys (only the minimal ones)
- One candidate key becomes the primary key
- The rest become alternate keys

---

## Summary

| Key | Unique | Minimal | NULL Allowed | Per Table |
|-----|--------|---------|--------------|-----------|
| Super Key | Yes | No | — | Many |
| Candidate Key | Yes | Yes | No | Many |
| Primary Key | Yes | Yes | No | Only 1 |
| Alternate Key | Yes | Yes | No | Many |
| Foreign Key | No | No | Yes | Many |
