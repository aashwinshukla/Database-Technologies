# Keys

## Why Keys?
- Used to uniquely identify rows in a table
- Used to establish relationships between tables
- Foundation of relational database design

---

## Candidate Key (Lec-9)

### Definition
- A minimal set of attributes that can uniquely identify a row
- Minimal = no subset of it can also uniquely identify the row
- A table can have multiple candidate keys

### Example — Student Table
| student_id | roll_no | name  | phone      |
|------------|---------|-------|------------|
| 1          | CS101   | Jack  | 9876543210 |
| 2          | CS102   | Kate  | 9876543211 |

- `student_id` → uniquely identifies → candidate key
- `roll_no` → uniquely identifies → candidate key
- `phone` → uniquely identifies → candidate key
- `name` → NOT unique → not a candidate key

### Key Points
- Every candidate key is minimal and unique
- One of the candidate keys is chosen as the primary key
- Remaining candidate keys become **alternate keys**

---

## Primary Key (Lec-10)

### Definition
- The candidate key chosen to uniquely identify rows in a table
- Only ONE primary key per table
- Cannot be NULL
- Cannot have duplicate values

### Choosing a Primary Key
- Prefer the simplest, most stable candidate key
- Avoid attributes that can change (e.g. name, phone number)
- Surrogate keys (auto-incremented IDs) are commonly used

### Example
```sql
CREATE TABLE student (
    student_id INT PRIMARY KEY,
    name VARCHAR(40),
    roll_no VARCHAR(10) UNIQUE
);
```
- `student_id` = primary key
- `roll_no` = alternate key (still unique, just not chosen as PK)

---

## Foreign Key (Lec-11)

### Definition
- An attribute in one table that references the primary key of another table
- Used to link two tables together
- Enforces referential integrity

### Example
```
Employee table: emp_id (PK), name, branch_id (FK → Branch.branch_id)
Branch table:   branch_id (PK), branch_name
```

### Rules
- FK value must exist as a PK in the referenced table OR be NULL
- Can have duplicate FK values (unlike PK)
- FK and PK must have compatible data types

---

## Insert, Update & Delete with Foreign Keys (Lec-12)

### Inserting
- Must insert into the referenced (parent) table first
- e.g. insert branch before inserting employee with that branch_id

### Deleting
- Cannot delete a parent row if a child row references it (by default)
- Use ON DELETE CASCADE or ON DELETE SET NULL to handle this

### Updating
- Cannot update a PK value if FK references exist (by default)
- Same ON DELETE rules apply for ON UPDATE

### Referential Integrity
- FK constraint ensures no orphan records
- DBMS automatically enforces this on every insert/update/delete

---

## Foreign Key Questions (Lec-13)

### Common Exam Scenarios
- Can FK be NULL? → Yes, unless NOT NULL constraint is added
- Can FK have duplicate values? → Yes
- Can FK reference a non-primary key? → Only if it's UNIQUE
- Can a table have multiple FKs? → Yes
- Can FK reference its own table? → Yes (self-referencing FK)
  - e.g. `super_id` in employee table referencing `emp_id` in the same table

---

## ON DELETE CASCADE (Lec-14)

### Definition
- When a parent row is deleted → all child rows with that FK are also deleted automatically

### Example
```sql
CREATE TABLE works_with (
    emp_id INT,
    client_id INT,
    FOREIGN KEY(emp_id) REFERENCES employee(emp_id) ON DELETE CASCADE
);
```
- Delete employee with emp_id = 5 → all works_with rows with emp_id = 5 are also deleted

### When to use
- When child rows have no meaning without the parent row
- When using composite primary keys (can't set to NULL)

## Super Key (Lec-15)

### Definition
- Any set of attributes that can uniquely identify a row
- Does NOT have to be minimal
- Every candidate key is a super key, but not every super key is a candidate key

### Example — Student Table
| student_id | roll_no | name |
|------------|---------|------|

- `{student_id}` → super key ✓
- `{roll_no}` → super key ✓
- `{student_id, roll_no}` → super key ✓ (but not minimal → not candidate key)
- `{student_id, name}` → super key ✓ (but not minimal)
- `{name}` → NOT unique → not a super key

### Relationship Between Keys
```
Super Key ⊇ Candidate Key ⊇ Primary Key
```
- All candidate keys are super keys
- Not all super keys are candidate keys (only minimal ones are)
- One candidate key is selected as primary key

## Notes
- Candidate key = minimal super key
- Primary key = chosen candidate key
- Alternate key = candidate key not chosen as primary key
- Foreign key creates relationships between tables
- ON DELETE CASCADE vs SET NULL depends on whether child can exist without parent
