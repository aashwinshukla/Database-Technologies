# Data Independence

## What is it?
- Ability to change the schema at one level without affecting another level
- One of the main goals of the three schema architecture
- Makes the system flexible and easier to maintain

---

## Types

### Logical Data Independence
- Change the **conceptual schema** without affecting **external schema** (user views)
- e.g. adding a new table or column should not break existing views or applications
- Harder to achieve — views are closely tied to the logical structure

### Physical Data Independence
- Change the **internal/physical schema** without affecting the **conceptual schema**
- e.g. changing file organization or adding an index should not affect logical structure
- Easier to achieve — most DBMS handle this well

---

## Where They Sit

```
[ External Level ]
        ↕  ← Logical Data Independence
[ Conceptual Level ]
        ↕  ← Physical Data Independence
[ Internal Level ]
```

---

## Analogy
- Physical independence: reorganizing a filing cabinet without changing what documents exist
- Logical independence: adding a new column to a table without breaking existing reports

---

## Notes
- Physical independence is more commonly achieved in modern DBMS
- Logical independence is harder but more valuable
- Data independence = reduced maintenance cost + more flexibility
