# Normal Forms

## Second Normal Form (2NF)

### Conditions
- Must already be in 1NF
- No partial dependencies — every non-key attribute must depend on the **whole** primary key, not just part of it
- Only relevant when the primary key is composite

### Example — NOT in 2NF
| student_id | course_id | student_name | course_name | grade |
|------------|-----------|--------------|-------------|-------|
| 1          | C01       | Jack         | Math        | A     |
| 1          | C02       | Jack         | Physics     | B     |

- PK = `(student_id, course_id)`
- `student_name` depends only on `student_id` → partial dependency → violates 2NF
- `course_name` depends only on `course_id` → partial dependency → violates 2NF

### Fixed — In 2NF
- Split into three tables:
  - `Student(student_id, student_name)`
  - `Course(course_id, course_name)`
  - `Enrollment(student_id, course_id, grade)`

## Third Normal Form (3NF)

### Conditions
- Must already be in 2NF
- No transitive dependencies — non-key attributes must depend **directly** on the primary key, not on another non-key attribute

### Example — NOT in 3NF
| student_id | name | dept_id | dept_name |
|------------|------|---------|-----------|
| 1          | Jack | D01     | CS        |
| 2          | Kate | D02     | Math      |

- PK = `student_id`
- `dept_name` depends on `dept_id`, not directly on `student_id`
- `student_id → dept_id → dept_name` → transitive dependency → violates 3NF

### Fixed — In 3NF
- `Student(student_id, name, dept_id)`
- `Department(dept_id, dept_name)`

### 3NF Formal Definition
- For every FD X → Y in the relation, either:
  - X is a superkey, OR
  - Y is a prime attribute (part of some candidate key)

---

## Boyce-Codd Normal Form (BCNF)

### What is it?
- A stricter version of 3NF
- Fixes anomalies that 3NF sometimes misses

### Condition
- For every FD X → Y, X must be a **superkey**
- No exceptions — unlike 3NF which allows Y to be a prime attribute

### Difference from 3NF
- 3NF allows: X → Y where Y is a prime attribute even if X is not a superkey
- BCNF does not allow this

### Example — In 3NF but NOT in BCNF
- Relation: `(student, course, teacher)`
- FDs: `{student, course} → teacher`, `teacher → course`
- Candidate keys: `{student, course}`, `{student, teacher}`
- `teacher → course` — teacher is not a superkey → violates BCNF
- But `course` is a prime attribute → satisfies 3NF

### Trade-off
- BCNF decomposition may not always preserve all functional dependencies
- 3NF always allows dependency-preserving decomposition
- BCNF always gives lossless decomposition

## Lossless and Lossy Decomposition

### Lossless Decomposition
- When a relation is decomposed, the original relation can be reconstructed by joining the decomposed tables
- No information is lost
- Required property — always aim for lossless decomposition

### Lossy Decomposition
- Joining decomposed tables produces extra (spurious) tuples not in the original relation
- Information is lost or corrupted
- Must be avoided

### Test for Lossless (Binary Decomposition)
- Decompose R into R1 and R2
- Lossless if: `R1 ∩ R2 → R1` OR `R1 ∩ R2 → R2`
- i.e. the common attributes form a superkey in at least one of the decomposed relations

## Fourth Normal Form (4NF)

### Condition
- Must be in BCNF
- No multi-valued dependencies (unless the determinant is a superkey)

### Multi-valued Dependency (MVD)
- A → →B (A multi-determines B)
- For a single value of A, there are multiple independent values of B
- e.g. a course can have multiple teachers AND multiple textbooks — independently

### Example — NOT in 4NF
| course | teacher | textbook  |
|--------|---------|-----------|
| Math   | Alice   | BookA     |
| Math   | Alice   | BookB     |
| Math   | Bob     | BookA     |
| Math   | Bob     | BookB     |

- `course →→ teacher` and `course →→ textbook` — independent MVDs → violates 4NF

### Fixed — In 4NF
- `CourseTeacher(course, teacher)`
- `CourseTextbook(course, textbook)`

---

## Fifth Normal Form (5NF)

### Condition
- Must be in 4NF
- No join dependencies — the relation cannot be decomposed into smaller relations without losing information, unless the join dependency is implied by candidate keys

### When it applies
- Rare in practice
- Deals with cases where a relation can only be reconstructed by joining 3+ tables
- If a relation has a join dependency that is NOT implied by its candidate keys → violates 5NF

---

## All Normal Forms — Summary

| NF | Eliminates |
|----|------------|
| 1NF | Non-atomic values, repeating groups |
| 2NF | Partial dependencies |
| 3NF | Transitive dependencies |
| BCNF | All non-superkey determinants |
| 4NF | Multi-valued dependencies |
| 5NF | Join dependencies |

---

## Notes
- Most real databases are designed to 3NF or BCNF
- BCNF is preferred but may sacrifice dependency preservation
- 4NF and 5NF are mostly theoretical in practice
- Always check for lossless decomposition when normalizing
- Normalization improves integrity but too much can hurt query performance
