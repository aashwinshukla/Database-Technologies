# Architecture

## 2-Tier Architecture (Lec-4)

### What is it?
- Client communicates directly with the database server
- Two layers: Client (presentation + application logic) and Database Server

### How it works
- Client sends request → Database server processes it → sends response back
- Application logic sits on the client side

### Real-life Example
- A desktop application (like a bank teller software) directly querying a database server
- Developer tools like MySQL Workbench connecting directly to MySQL

### Advantages
- Simple and fast
- Easy to set up for small applications

### Disadvantages
- Not scalable — too many clients = overloaded DB server
- Business logic exposed on client side — security risk
- Changes to logic require updating every client

---

## 3-Tier Architecture (Lec-4)

### What is it?
- Three layers: Client → Application Server → Database Server
- Client never talks directly to the database

### Layers
1. **Presentation Layer (Client)** — UI, browser, mobile app
2. **Application Layer (Middle Tier)** — business logic, API, web server
3. **Database Layer** — actual database server

### Real-life Example
- User fills a form on a website → goes to web server (Node.js/Django) → web server queries the DB → sends result back to user

### Advantages
- More secure — DB not directly exposed to client
- Scalable — middle tier can be scaled independently
- Business logic centralized on the server
- Easier to maintain and update

### Disadvantages
- More complex to set up
- Slightly more latency due to extra layer

## What is a Schema? (Lec-5)

### Definition
- A schema is the logical structure/blueprint of a database
- Defines tables, columns, data types, relationships, constraints
- Does NOT contain the actual data — just the structure

### Analogy
- Schema = blueprint of a house
- Data = the actual furniture and people inside

### Types
- **Physical Schema** — how data is physically stored on disk
- **Logical Schema** — overall logical structure of the database
- **View Schema** — what specific users can see (subsets of logical schema)

## Three Schema Architecture (Lec-6)

### Also called: Three Level Architecture / ANSI-SPARC Architecture

### Three Levels

#### 1. External Level (View Level)
- What individual users or user groups see
- Different users can have different views of the same data
- e.g. HR sees employee salary, employee sees only their own salary

#### 2. Conceptual Level (Logical Level)
- Overall logical structure of the entire database
- Describes what data is stored and relationships between them
- Hides physical storage details
- Defined by the DBA (Database Administrator)

#### 3. Internal Level (Physical Level)
- Actual physical storage of data on disk
- Deals with file organization, indexing, access paths
- Closest to hardware

### Diagram
```
[ External Level ]  ← Users / Applications
        ↕
[ Conceptual Level ] ← DBA / Logical Design
        ↕
[ Internal Level ]   ← Physical Storage / Disk
```

### Why Three Levels?
- Achieve data independence
- Changes at one level don't affect other levels
- Multiple views of the same data for different users

---

## Notes
- Most modern web apps use 3-tier architecture
- Three schema architecture is a conceptual framework — not always implemented exactly as described
- External level = multiple views; Conceptual = one logical schema; Internal = one physical schema
