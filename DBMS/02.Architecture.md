# Architecture

## 2-Tier Architecture

- Two layers: Client and Database Server
- Client holds both the UI and application logic
- Client talks directly to the database

### Example
- A desktop app querying a database server directly
- MySQL Workbench connecting to a MySQL server

### Pros
- Simple, fast, easy to set up
- Good for small applications

### Cons
- Not scalable — many clients overload the DB server
- Business logic on the client = security risk
- Any logic change requires updating every client

---

## 3-Tier Architecture

- Three layers: Client → Application Server → Database Server
- Client never touches the database directly

### Layers
1. **Presentation Layer** — UI (browser, mobile app)
2. **Application Layer** — business logic, APIs, web server
3. **Database Layer** — actual database

### Example
- User submits a form → goes to a Node.js/Django server → server queries the DB → response sent back

### Pros
- More secure — DB not exposed to client
- Scalable — each layer can scale independently
- Business logic centralized
- Easier to maintain

### Cons
- More complex setup
- Slight latency from the extra layer

## Schema

- A schema is the logical blueprint/structure of a database
- Defines tables, columns, data types, relationships, constraints
- Does not contain actual data — just the structure

### Analogy
- Schema = blueprint of a building
- Data = the actual contents inside

### Types
- **Physical Schema** — how data is stored on disk
- **Logical Schema** — overall logical structure
- **View Schema** — what a specific user/group can see

---

## Three Schema Architecture (ANSI-SPARC)

### Three Levels

#### External Level (View Level)
- What individual users or groups see
- Different users can have different views of the same data
- e.g. HR sees salaries, employees only see their own

#### Conceptual Level (Logical Level)
- Overall logical structure of the entire database
- Describes what data exists and relationships between them
- Hides physical storage details

#### Internal Level (Physical Level)
- Actual physical storage on disk
- File organization, indexing, access paths
- Closest to the hardware

### Diagram
```
[ External Level ]   ← Users / Applications
        ↕
[ Conceptual Level ] ← Logical Design
        ↕
[ Internal Level ]   ← Physical Storage / Disk
```

### Why Three Levels?
- Achieve data independence
- Changes at one level don't affect others
- Multiple views of the same data for different users

---

## Notes
- Most modern web apps use 3-tier architecture
- Three schema architecture is a conceptual framework
- External level = many views; Conceptual = one logical schema; Internal = one physical schema
