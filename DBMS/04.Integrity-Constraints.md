# Integrity Constraints

## What are Integrity Constraints?
- Rules enforced on data in a database to maintain accuracy and consistency
- Applied at the schema level — automatically checked by DBMS
- If a constraint is violated → the operation is rejected

---

## Types of Integrity Constraints

### 1. Domain Constraint
- Defines valid values for an attribute
- Specifies data type, range, format
- e.g. age must be an integer between 0 and 150
- e.g. sex must be 'M' or 'F'

### 2. Entity Integrity Constraint
- Every table must have a primary key
- Primary key cannot be NULL
- Ensures every row is uniquely identifiable
- e.g. student_id cannot be NULL or duplicate

### 3. Referential Integrity Constraint
- A foreign key value must either match an existing primary key in the referenced table OR be NULL
- Ensures relationships between tables are valid
- e.g. if emp_id = 5 in works_with, there must be an employee with emp_id = 5
- Prevents orphan records

### 4. Key Constraint
- A primary key must be unique across all rows
- No two rows can have the same primary key value
- Closely related to entity integrity

### 5. Tuple Uniqueness Constraint
- All rows (tuples) in a table must be unique
- No two rows can be completely identical in all attributes

---

## How Constraints are Enforced
- Defined during `CREATE TABLE` or `ALTER TABLE`
- DBMS checks constraints on every `INSERT`, `UPDATE`, `DELETE`
- Violation → transaction is rejected/rolled back

---

## Notes
- Constraints = rules baked into the schema, not the application
- Better to enforce at DB level than application level — more reliable
- Domain constraints are the most basic level of data validation
- Referential integrity is critical in relational databases with multiple tables
