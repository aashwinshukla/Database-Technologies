# Integrity Constraints

## What are they?
- Rules enforced on data to maintain accuracy and consistency
- Applied at the schema level — automatically checked by the DBMS
- If violated → the operation is rejected

---

## Types

### Domain Constraint
- Defines valid values for an attribute
- Specifies data type, range, or format
- e.g. age must be an integer between 0 and 150
- e.g. sex must be 'M' or 'F'

### Entity Integrity Constraint
- Every table must have a primary key
- Primary key cannot be NULL
- Ensures every row is uniquely identifiable

### Referential Integrity Constraint
- A foreign key value must either match an existing primary key in the referenced table OR be NULL
- Prevents orphan records
- e.g. if branch_id = 3 in employee, there must be a branch with branch_id = 3

### Key Constraint
- Primary key must be unique across all rows
- No duplicates allowed

### Tuple Uniqueness Constraint
- All rows in a table must be distinct
- No two rows can be completely identical in all attributes

---

## How Constraints Work
- Defined in `CREATE TABLE` or `ALTER TABLE`
- DBMS checks them on every `INSERT`, `UPDATE`, `DELETE`
- Violation → operation rejected

---

## Notes
- Better to enforce rules at the DB level than in application code — more reliable
- Domain constraints are the most basic form of data validation
- Referential integrity is critical in multi-table relational databases
