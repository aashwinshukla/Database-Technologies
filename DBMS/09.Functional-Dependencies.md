# Functional Dependencies

## What is a Functional Dependency?
- A constraint between two sets of attributes in a relation
- Attribute B is functionally dependent on attribute A if each value of A determines exactly one value of B
- Written as: A → B (A determines B)
- e.g. `student_id → name` — knowing the student_id tells you exactly one name

---

## Terminology
- **Determinant** — the attribute on the left side (A)
- **Dependent** — the attribute on the right side (B)
- If A → B, then A is the determinant and B is the dependent

---

## Types of Functional Dependencies

### Trivial FD
- B is a subset of A
- A → B where B ⊆ A
- e.g. `{student_id, name} → student_id` — always true, not useful
- Called trivial because it adds no new information

### Non-Trivial FD
- B is NOT a subset of A
- e.g. `student_id → name` — useful dependency
- Most FDs we care about are non-trivial

### Partial Dependency
- A non-key attribute depends on only **part** of a composite primary key
- Violates 2NF
- e.g. PK = `(student_id, course_id)`, but `student_name → student_id` only
  - `student_name` depends only on `student_id`, not the full composite key

### Transitive Dependency
- A non-key attribute depends on another non-key attribute
- Violates 3NF
- e.g. `student_id → dept_id → dept_name`
  - `dept_name` depends on `dept_id`, not directly on `student_id`

---

## Armstrong's Axioms (Properties of FDs)

### Reflexivity
- If B ⊆ A, then A → B
- e.g. `{name, age} → name`

### Augmentation
- If A → B, then AC → BC (adding same attribute to both sides)
- e.g. if `student_id → name`, then `{student_id, age} → {name, age}`

### Transitivity
- If A → B and B → C, then A → C
- e.g. `student_id → dept_id` and `dept_id → dept_name`, so `student_id → dept_name`

### Derived Rules (from the above)
- **Union**: if A → B and A → C, then A → BC
- **Decomposition**: if A → BC, then A → B and A → C
- **Pseudotransitivity**: if A → B and BC → D, then AC → D

## Closure of a Set of Attributes (F+)

### What is it?
- The set of all attributes that can be functionally determined by a given set of attributes
- Written as X⁺ (closure of X)

### How to find closure
1. Start with X⁺ = X
2. For each FD A → B, if A ⊆ X⁺, add B to X⁺
3. Repeat until no more attributes can be added

### Example
- Relations: A → B, B → C, A → D
- Find closure of {A}
  - Start: {A}
  - A → B → add B: {A, B}
  - B → C → add C: {A, B, C}
  - A → D → add D: {A, B, C, D}
  - Closure of A = {A, B, C, D}

### Why it's useful
- To check if a set of attributes is a candidate key (closure = all attributes)
- To find what a given attribute can determine
- Used in finding minimal cover

---

## Minimal Cover (Canonical Cover)

### What is it?
- A simplified, minimal set of FDs that is equivalent to the original set
- No redundant FDs, no redundant attributes on the left side

### Steps to find Minimal Cover
1. **Right-hand side simplification** — break all FDs so RHS has only one attribute
   - e.g. A → BC becomes A → B and A → C
2. **Left-hand side simplification** — remove redundant attributes from LHS
   - Check if removing an attribute from LHS still gives the same closure
3. **Remove redundant FDs** — check if any FD can be derived from the others
   - If yes, remove it

### Example
- FDs: A → BC, B → C, AB → C
- Step 1: A → B, A → C, B → C, AB → C
- Step 2: check AB → C — can A alone determine C? A → C exists → yes, so AB → C is redundant → remove
- Step 3: check A → C — can it be derived? A → B and B → C → A → C by transitivity → redundant → remove
- Minimal cover: {A → B, B → C}

---

## Cover and Equivalence of FD Sets

### Covers
- A set F covers G if every FD in G can be derived from F
- i.e. every FD in G is in F⁺

### Equivalence
- Two sets F and G are equivalent if F covers G AND G covers F
- They produce the same closure
- Written as F ≡ G

---

## Notes
- Functional dependencies are the basis for normalization
- Finding closure is key to identifying candidate keys
- Minimal cover is used when decomposing relations into 3NF
- Armstrong's axioms are sound (don't generate incorrect FDs) and complete (can derive all valid FDs)
