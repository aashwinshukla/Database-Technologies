# ER Model

## What is it?
- Entity Relationship Model
- A high-level conceptual data model
- Used to design the database structure before implementation
- Represented visually as an ER diagram

---

## Entity
- A real-world object or concept that has data stored about it
- Represented as a **rectangle**
- e.g. Student, Employee, Course, Branch

### Entity Set
- A collection of similar entities
- e.g. all students in a university = Student entity set

---

## Attributes
- Properties or characteristics of an entity
- Represented as **ovals** connected to the entity

### Types of Attributes

#### Simple Attribute
- Cannot be divided further
- e.g. `age`, `student_id`

#### Composite Attribute
- Can be broken down into smaller sub-attributes
- e.g. `full_name` → `first_name` + `last_name`
- e.g. `address` → `street` + `city` + `zip`

#### Single-valued Attribute
- Holds only one value for an entity
- e.g. `date_of_birth` — a person has only one

#### Multi-valued Attribute
- Can hold multiple values for a single entity
- Represented with a **double oval**
- e.g. `phone_numbers` — a person can have multiple

#### Derived Attribute
- Value can be computed from another attribute
- Represented with a **dashed oval**
- e.g. `age` derived from `date_of_birth`
- Not physically stored — calculated when needed

#### Key Attribute
- Uniquely identifies an entity within the entity set
- Underlined in the ER diagram
- e.g. `student_id`, `emp_id`

---

## Relationship
- An association between two or more entities
- Represented as a **diamond**
- e.g. Student **enrolls in** Course, Employee **works for** Branch

### Degree of Relationship
- **Unary** — relationship between instances of the same entity (self-referencing)
  - e.g. Employee **manages** Employee
- **Binary** — between two different entities (most common)
  - e.g. Student **enrolls in** Course
- **Ternary** — between three entities
  - e.g. Doctor **prescribes** Medicine **to** Patient

---

## Notes
- ER diagram is database-agnostic — not tied to any specific DBMS
- Designed before writing any SQL
- Every entity becomes a table, every attribute becomes a column
- Tools: draw.io, Lucidchart, MySQL Workbench
