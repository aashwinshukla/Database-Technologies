# SQL - Introduction and Commands

## What is SQL?
- Structured Query Language
- Used to interact with relational databases
- Declarative — you say what you want, not how to get it
- Based on relational algebra and tuple calculus concepts
- Standard language across most RDBMS (MySQL, PostgreSQL, Oracle, SQL Server)

---

## Characteristics of SQL
- Not case-sensitive (keywords conventionally written in CAPS)
- Statements end with a semicolon `;`
- Can perform CRUD — Create, Read, Update, Delete
- Supports constraints, transactions, views, stored procedures, triggers

---

## Types of SQL Commands

### DDL — Data Definition Language
- Defines and modifies the structure of the database
- Changes are auto-committed (cannot be rolled back in most RDBMS)

| Command | Purpose |
|---------|---------|
| `CREATE` | Create a new table, database, index, view |
| `ALTER` | Modify an existing table structure |
| `DROP` | Delete a table or database permanently |
| `TRUNCATE` | Remove all rows from a table (keeps structure) |
| `RENAME` | Rename a table or column |

---

### DML — Data Manipulation Language
- Used to manipulate data inside tables
- Changes can be rolled back (part of a transaction)

| Command | Purpose |
|---------|---------|
| `INSERT` | Add new rows |
| `UPDATE` | Modify existing rows |
| `DELETE` | Remove specific rows |
| `SELECT` | Retrieve data (sometimes classified as DQL) |

---

### DCL — Data Control Language
- Controls access and permissions

| Command | Purpose |
|---------|---------|
| `GRANT` | Give privileges to a user |
| `REVOKE` | Remove privileges from a user |

---

### TCL — Transaction Control Language
- Manages transactions and ensures data integrity

| Command | Purpose |
|---------|---------|
| `COMMIT` | Save all changes made in the current transaction |
| `ROLLBACK` | Undo changes made since last COMMIT |
| `SAVEPOINT` | Set a point within a transaction to rollback to |

---

### DQL — Data Query Language
- Sometimes separated from DML

| Command | Purpose |
|---------|---------|
| `SELECT` | Retrieve/query data from tables |

---

## Constraints in SQL
- Rules applied to columns to enforce data integrity
- Defined at column or table level

| Constraint | Purpose |
|------------|---------|
| `NOT NULL` | Column cannot have NULL value |
| `UNIQUE` | All values must be distinct |
| `PRIMARY KEY` | NOT NULL + UNIQUE, identifies each row |
| `FOREIGN KEY` | References PK in another table |
| `CHECK` | Value must satisfy a condition |
| `DEFAULT` | Assigns a default value if none provided |

---

## Notes
- DDL changes the structure, DML changes the data
- TCL only applies to DML operations — DDL is auto-committed
- `SELECT` is technically DQL but often grouped under DML
- Constraints enforce integrity at the database level — more reliable than application-level checks
